# v0.4 Artifact Explorer

HDL Dev exposes generated HDL outputs through a native Artifacts tree. The tree
is a passive index over project-local output directories; it does not create,
delete, or rewrite artifacts during discovery.

## Discovery Contract

Artifact discovery reuses the passive HDL project discovery model. A project is
eligible when it has a `Makefile` and at least one spec directory:

```text
docs/waveforms/specs
docs/schematics/specs
```

For each discovered project, HDL Dev scans these artifact locations:

```text
build/waves/*.ghw
build/waves/*.fst
build/waves/*.vcd
docs/waveforms/generated/*.svg
docs/schematics/generated/*.svg
build/schematics/**/*.json
logs/**/*.log
logs/**/*.txt
logs/plots/*.svg
logs/plots/*.png
logs/plots/*.jpg
logs/plots/*.jpeg
logs/plots/*.pdf
build/csv/**/*.csv
```

Missing artifact directories are normal. Discovery keeps them as empty groups so
the tree can explain which workflow produces that artifact type.

## VS Code Surface

The extension contributes an `Artifacts` view under the `HDL` Activity Bar
container. The view is shown when passive discovery finds at least one HDL
project.

The Artifacts view exposes the manual refresh command:

```text
HDL Dev: Refresh Artifacts
HDL Dev: Open Artifact
HDL Dev: Reveal Artifact in File Explorer
HDL Dev: Copy Artifact Path
```

The same refresh is also wired to workspace folder changes,
`hdlDev.projectRoots` configuration changes, file create/change/delete events
under known artifact directories, successful waveform and schematic SVG
generation commands, and completed testbench runs.

## Tree Shape

The tree groups artifacts first by project, then by generated artifact type:

```text
HDL
  Artifacts
    timer
      Wave Dumps
        timer_tb.ghw
      Waveform SVGs
        timer-wave.svg
      Schematic SVGs
        timer-core.svg
      Schematic JSON
        timer-core.json
      Logs
        run.log
      Plots
        latency.svg
      CSV Outputs
        results.csv
```

Project item labels use the project directory name and include the absolute
project root as description and tooltip. Artifact item IDs include the project
root, artifact kind, and absolute artifact path so IDs remain stable across tree
refreshes for the same checkout.

Selecting an artifact or choosing `HDL Dev: Open Artifact` opens it in the
normal VS Code editor. SVGs, logs, JSON, CSV, wave dumps, and supported image
files therefore use standard editor behavior until the extension grows dedicated
preview surfaces.

Artifact context menus also expose `Reveal Artifact in File Explorer` and
`Copy Artifact Path`. Reveal uses VS Code's platform file reveal command. Copy
path writes the absolute artifact path to the VS Code clipboard so command
output and generated file locations remain easy to report in diagnostics.

## Artifact Groups

The stable group labels are:

```text
Wave Dumps
Waveform SVGs
Schematic SVGs
Schematic JSON
Logs
Plots
CSV Outputs
```

Each group reports the number of currently indexed artifacts. Empty groups keep
their place in the tree and describe the command family that can produce them,
for example running a testbench for wave dumps or generating a schematic SVG for
schematic JSON.

## Performance And Trust

Artifact discovery is passive file reading:

```text
executedWorkspaceCommands: false
requiresWorkspaceTrust: false
```

It is allowed before the workspace is trusted because it does not run Make,
GHDL, Python, Yosys, `netlistsvg`, or project scripts.

Refresh is asynchronous and is started without blocking extension activation.
Each artifact group is capped during discovery so very large output directories
do not require an unbounded scan before the tree can update. Capped groups are
marked with a truncation status node.

## Current Limits

- The first Artifact Explorer slice opens files with the normal editor only.
- The "open latest artifact" command is planned follow-up work.
- Stale-artifact indicators comparing specs and outputs are not implemented
  yet.
- Debug-session grouping for packetized-I/O logs, plots, and CSVs is deferred to
  the later packetized-I/O milestone.
